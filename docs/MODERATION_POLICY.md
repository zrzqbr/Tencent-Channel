# QQ 频道内容审核与治理规则

当前策略基线：`2026-08-19.ai2`

## 基本原则

1. 分类错误、内容过短、没有话题、疑似乱码等主观问题，只进入人工复核，不直接删除。
2. 每次判断必须保存规则编号、风险等级、命中证据、建议动作、策略版本和最终操作结果。
3. 自动删除默认关闭。配置文件中的 `delete_mode`、对应自动删除开关和规则资格必须同时满足，才允许调用删除接口。
4. 新规则先在 `dry_run` 下运行并观察误判，再考虑启用自动操作。

## 审核流水线

内容依次经过以下阶段：

1. 文本标准化：统一全半角、大小写、空白和零宽字符。
2. 敏感词检测：中文子串、英文单词边界、简单分隔规避（如 `s-b`）。
3. 信息筛查：手机号、邮箱、QQ/微信账号和外部链接。
4. 内容质量：极短内容、重复字符、疑似无语义英文字母组合。
5. VITA 图片理解：提取图片主体、OCR 文字、联系方式、二维码、风险线索及图文关联。
6. Hy3 语义审核：结合完整正文、图片证据、同版块相邻内容和规则信号输出严格结构化结论。
7. 自动分类：精华、每周一问、实用文章、问答与交流、官方资讯、待确认。
8. 版块规则：判断分类是否符合所在版块、话题是否必需、最小长度和外链限制。
9. 严格去重：只比较同一频道、同一栏目中相邻的两条内容。
10. 动作决策：放行、人工复核、删除候选；最后记录完整审计信息。

帖子正文、图片文字和外部链接内容始终作为不可信数据处理，不能改变系统规则。AI 只返回建议、证据和置信度，不具有删除权限。VITA 无法分析图片时强制转人工；Hy3 不可用时安全降级为规则结果。

## 分类规则

| 栏目 | 主要依据 |
| --- | --- |
| 每周一问 | 必须带井号话题；正文只有“每周一问”语义但没有话题时进入复核 |
| 实用文章 | 图文结合，并达到文章长度或包含案例、教程、复盘、步骤等特征；文章内部的示例问号不再优先判成问答 |
| 问答与交流 | 固定交流版块；或标题明显提问；或短正文包含求助、讨论表达 |
| 精华 | 默认需要显式 `#精华`；长图文只标记为精华候选，不自动授予精华 |
| 官方资讯 | 显式官方话题、固定官方版块或官方作者白名单 |
| 待管理员确认 | 证据不足，不能稳定进入任何栏目 |

## 风险与动作

| 风险分 | 风险等级 | 默认动作 |
| ---: | --- | --- |
| 0–24 | low | 放行，可保留低风险提示 |
| 25–49 | medium | 人工复核 |
| 50–79 | high | 人工复核 |
| 80–100 | critical | 删除候选，仍不代表已经删除 |

只有敏感词规则中明确设置为 `delete_candidate` 的规则才具有“策略自动删除资格”。多个低质量问题即使累计达到高分，也不能自动删除。

当前生产策略关闭普通违规内容自动删除。只有“同作者、同频道、同栏目、连续且标准化后完全一致”的确定性重复内容允许自动去重。

## 严格删除规则

### 连续重复

只有全部满足以下条件，后一条内容才是删除候选：

- 同一个 QQ 频道；
- 同一个分类栏目；
- 在该栏目时间顺序中相邻；
- 作者相同；
- 标题、正文、图片和视频在标准化后完全一致；
- 不是平台事件的重复投递；
- 审计记录中保存上一条内容 ID 和完整内容指纹。

模糊相似、不同作者、跨栏目和中间出现其他同类内容的情况都不能自动删除。

### 敏感或违规内容

自动删除必须同时满足：

- 命中明确配置的敏感词规则；
- 该规则的动作是 `delete_candidate`；
- 规则原因的 `auto_delete_eligible=true`；
- `auto_delete_policy_violations=true`；
- `delete_mode=live`。

辱骂、外链、联系方式、低质量、错投版块默认只复核。上下文可能是引用、科普或安全教育时，应由管理员判断。

## 主要理由代码

| 理由代码 | 含义 |
| --- | --- |
| `sensitive_term_zh` / `sensitive_term_en` | 命中中文或英文敏感词 |
| `contact_information_detected` | 检测到手机号、邮箱、QQ 或微信等信息 |
| `external_link_detected` | 检测到外部链接 |
| `external_link_not_allowed` | 当前版块禁止外链 |
| `low_information_content` | 有效信息量不足 |
| `repeated_characters` | 主要由重复字符组成 |
| `possible_gibberish` | 疑似无语义英文字母组合 |
| `classification_uncertain` | 无法稳定分类 |
| `section_mismatch` | 内容类型与所在版块不一致 |
| `required_hashtag_missing` | 缺少版块要求的话题 |
| `missing_weekly_hashtag` | 每周一问缺少井号话题 |
| `exact_consecutive_duplicate` | 同作者、同栏目、连续、完全一致 |

## 新增版块

每个新 QQ 版块需要在 `board_policies` 中配置：

- 版块名称；
- 允许的栏目类型；
- 是否要求井号话题；
- 最低有效文字长度；
- 是否允许外部链接。

固定版块还需要在 `channel_sections` 和对应 `tencent_channels[].channels` 中登记。混合内容入口放入 `auto_classify_channels`，系统会先分类，再按分类进行去重。

## 可视化后台数据

SQLite 已保存或预留以下字段，可直接作为后台接口的数据来源：

- 内容 ID、频道 ID、版块 ID、作者 ID；
- 分类、分类置信度、分类理由；
- 风险等级、风险分、策略版本；
- 建议动作、全部理由和证据；
- 重复内容的上一条 ID；
- 人工审核状态与审核记录；
- 删除状态、失败原因和操作时间。

本地命令：

```bash
# 测试一条内容，不连接 QQ
qq-guard --config config.json moderate --channel 版块ID --body '待测试内容'

# 查看待审核队列
qq-guard --config config.json audit --review-only

# 输出后台仪表盘汇总 JSON
qq-guard --config config.json dashboard
```

正式做网页时，服务端应增加登录、角色权限、CSRF 防护、操作二次确认和不可篡改审计日志；不能把本地 SQLite 或腾讯凭据直接暴露给浏览器。
